# 当前 Planner GRPO：代码与结果

本目录归档截至 2026-10-30 已完成的 Planner GRPO 训练、Val422 评估及诊断。训练主版本为 `finance_program_grpo_full_migrated_20261027_r3`，评估为 `finance_program_grpo_val422_20261028_r4`。原始 Python 文件按字节复制，未为上传修改训练算法、模型路由、提示或评估规则。

## 已记录结果

训练使用固定 48 个来源，每个来源 4 条轨迹，共 192 条，完成 6 次实际参数更新。奖励为合法分类及等级同时正确的 A1 二值信号；仅更新 Planner，Skill 使用冻结基座。训练联合正确 117/192，合法预测 186/192，3 条技术失败仍保留在原分母。采样与训练概率差异使用 token TIS（上限 2）校正，具体实现见 `policy_math.py` 和 `policy_update.py`。

| Val422 指标 | 历史 SFT | 当前 GRPO version06 |
|---|---:|---:|
| 分类正确 | 138/422 | 134/422 |
| 等级正确 | 217/422 | 213/422 |
| 分类及等级联合正确 | 138/422（32.70%） | 134/422（31.75%） |
| 合法预测 | 407/422 | 417/422 |
| 弃权 | 14/422 | 4/422 |
| 固定 12 类 Macro F1 | 0.1760 | 0.1666 |
| 模型调用 | 3344 | 3395 |

按来源匹配：20 条改善、24 条退步、114 条均正确、264 条均不正确，联合正确净少 4 条（约 0.95 个百分点）。GRPO 的 1 条实际生成失败保留在 422 分母。合法完成率不等于业务正确率。

Val422 曾用于开发，不是全新独立测试集。两轮公开输入、来源及终止规则的字节身份已核对，但硬件、环境及运行包装不同，完整执行条件等价未获确认。不能将本次比较表述为严格因果消融、统计显著提升或下降。未完成全部业务语义的人工审核。

## 目录

- `experiments/finance_program_grpo_full_migrated_20261027_r3/`：训练、奖励、概率校正、检查点、预算与资源约束，以及原有单元测试。
- `experiments/finance_program_grpo_val422_20261028_r4/`：评估入口、实际模型路由与检查点验收、预算及原有测试。
- `experiments/dependencies/`：两版冻结清单中实际使用的 Python 依赖，保留原实验目录名和版本链。它们包含既有 SFT 模型后端、输入接口和 native 执行器；不是本次新增 SFT 训练。
- `analysis/`：原有计分、诊断和审核脚本。它们使用原始归档目录布局，完整重放需要自行恢复归档和输入。
- `results/`：原有训练验收、独立审核、完整来源级评分、失败记录、诊断报告，以及便于读取的 `summary.json`。
- `provenance/`：历史完整冻结清单及未上传资产的路径、SHA256 和原因。
- `publication-manifest.json`：发布文件的 SHA256、大小和本地来源；原文件复制项标记 `exact_source_bytes=true`。

## 本地检查

Python 3.13 与 PyTorch 2.9.0 环境可运行以下不启动 GPU、完整模型推理或训练任务的检查：

```bash
python -B verify_publication.py
```

该命令核对全部发布文件的 SHA256，解析 Python 语法，并运行与数据及部署环境无关的原有测试：训练数值、概率校正、奖励、预算、检查点往返、资源与恢复合同，以及评估检查点和进程身份测试。测试里的微型张量更新在 CPU 上执行，不是新的实验训练。

未上传的数据对应的 cohort 测试、依赖原部署目录的 admission 测试，以及运维脚本测试不在这组便携检查内。它们不能因为本地检查通过就被表述为重新验收通过。历史完整 native 验收结果见 `results/`，本次发布不重跑旧原生轨迹。
