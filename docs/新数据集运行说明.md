# TransClass 新数据集运行说明

## 一、放置原始数据

将 CSV 或 XLSX 文件放到：

    data/raw/<dataset>.xlsx

也支持：

    data/raw/<dataset>.csv
    data/raw/<dataset>s.xlsx
    data/raw/<dataset>s.csv

建议优先使用与 dataset 完全同名的文件。如果同时存在多个候选文件，
程序会停止并要求通过 --input 明确指定，避免选错数据。

数据必须包含可映射为 field_name 的字段名列。


## 二、创建映射

在以下目录创建：

    script/preprocessing/mappings/<dataset>.json

示例：

{
  "数据库名": "database_name",
  "表名": "table_name",
  "表描述": "table_description",
  "字段名": "field_name",
  "字段描述": "field_description",
  "字段类型": "field_type",
  "一级分类": "level_1",
  "二级分类": "level_2",
  "三级分类": "level_3",
  "四级分类": "level_4",
  "分级": "data_level"
}

原始数据没有的字段不需要写入 mapping，程序会补为空字符串。


## 三、一条命令完成预处理和切分

在 transclass 项目根目录运行：

    python -m script.preprocessing.cli prepare --dataset <dataset>

例如：

    python -m script.preprocessing.cli prepare --dataset shougang

默认行为：

    从 data/raw/<dataset>.xlsx、.csv 或复数形式自动寻找原始文件；
    使用 script/preprocessing/mappings/<dataset>.json；
    跳过 field_name 为空的表级记录；
    按 metadata.table_name 分组；
    跳过 metadata.table_name 为空、无法参与按表分组的记录；
    按 0.8/0.1/0.1 切分；
    输出到 data/processed/<dataset>/。

所有跳过操作都会在终端显示警告。分组阶段跳过的数量、原因和索引
还会写入 split_report.json，不会静默丢弃。

重新生成已有输出时加入：

    python -m script.preprocessing.cli prepare --dataset <dataset> --overwrite

输出文件：

    data/processed/<dataset>/all.json
    data/processed/<dataset>/train.json
    data/processed/<dataset>/val.json
    data/processed/<dataset>/test.json
    data/processed/<dataset>/split_report.json

all.json 保存预处理后的完整有效记录。仅因 group_key 为空而被跳过的记录
仍会保留在 all.json 中，但不会进入 train.json、val.json 或 test.json。


## 四、常用参数

指定原始文件：

    --input <path>

指定 mapping：

    --mapping <path>

随机切分：

    --split-type random

按表分组切分：

    --split-type group --group-key metadata.table_name

使用其他字段分组：

    --split-type group --group-key metadata.database_name

缺失分组字段时跳过（prepare 默认）：

    --missing-group-policy skip

缺失分组字段时严格报错（split 默认）：

    --missing-group-policy error

缺少 field_name 时跳过（prepare 默认）：

    --missing-field-policy skip

缺少 field_name 时严格报错（preprocess 默认）：

    --missing-field-policy error

修改比例：

    --train-ratio 0.8 --val-ratio 0.1 --test-ratio 0.1

修改随机种子：

    --seed 42

列出已经发现的 mapping：

    python -m script.preprocessing.cli list-datasets


## 五、分别执行预处理和切分

只执行预处理：

    python -m script.preprocessing.cli preprocess `
      --dataset <dataset> `
      --input data/raw/<dataset>.xlsx `
      --output data/processed/<dataset>/all.json `
      --missing-field-policy skip `
      --overwrite

只执行切分：

    python -m script.preprocessing.cli split `
      --input data/processed/<dataset>/all.json `
      --output-dir data/processed/<dataset> `
      --type group `
      --group-key metadata.table_name `
      --missing-group-policy skip `
      --overwrite


## 六、生成 RFT JSONL

    python -m script.preprocessing.rft_export `
      --input-dir data/processed/<dataset> `
      --output-dir data/rft/<dataset>

生成 train.jsonl、val.jsonl、test.jsonl 和 export_report.json。
只有 labeled 数据会进入 RFT 文件。


## 七、注意事项

1. group 模式保证同一张表不跨 train/val/test，适合评估新表泛化。
2. group 模式不能拆分一个组，因此实际数量通常只能接近 0.8/0.1/0.1，
   不保证逐条精确等于目标比例。
3. group_key 为空的记录默认不会进入 train/val/test。缺失较多时，应修复
   源数据、使用其他可靠 group_key，或改用 random。
4. random 模式可以严格满足全局数量比例，但同一张表可能同时出现在
   train、val 和 test 中。
5. field_name 为空的记录无法形成字段级样本，prepare 默认跳过。
6. 去重身份由 database_name、table_name、field_name 三个字段组成。
   三者相同且分类分级一致时只保留第一条；分类分级冲突时程序报错。
   这不等同于要求整行所有字段完全相同。
7. split_report.json 中的 warnings 表示标签覆盖不完整。
   labels_missing_from_train 需要重点处理，因为模型无法学习训练集中不存在
   的标签；其他 warning 通常表示 val/test 未覆盖部分训练标签。
8. data/raw 和 data/processed 已被 .gitignore 忽略，不会默认加入 Git。
   data/rft 和 data/corpus 也已被忽略。提交前仍应运行 git status 检查，
   避免数据文件进入版本控制。


## 八、生成检索语料库 Corpus

指南类 CSV 或 XLSX 默认命名为：

    data/raw/<dataset>-content.xlsx

其中至少包含：

    四级子类
    内容

在项目根目录运行：

    python -m script.corpus.cli build --dataset <dataset> --overwrite

例如：

    python -m script.corpus.cli build --dataset finance --overwrite

程序会自动：

    读取 data/raw/finance-content.xlsx；
    每一行生成一篇独立语料文档；
    将“内容”列作为用于检索的 text；
    将四级子类、来源和原始行号写入 metadata；
    使用 data/processed/finance/all.json 统计标签覆盖情况；
    输出到 data/corpus/finance/。

输出文件：

    data/corpus/<dataset>/corpus.json
    data/corpus/<dataset>/build_report.json

corpus.json 用于 RAG 或向量检索，不是模型微调数据。
build_report.json 记录输入行数、跳过记录、重复记录、分类数量及与
processed 数据的标签覆盖关系。

指定其他输入文件、processed 文件或输出目录：

    python -m script.corpus.cli build `
      --dataset <dataset> `
      --input <guide.xlsx> `
      --processed data/processed/<dataset>/all.json `
      --output-dir data/corpus/<dataset> `
      --overwrite

默认一行指南生成一篇文档。只有当单行内容非常长时才需要进一步切块；
当前 finance-content.xlsx 的内容较短，不需要切块或按分类合并。
