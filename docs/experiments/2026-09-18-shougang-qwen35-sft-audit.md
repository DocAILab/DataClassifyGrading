# Shougang Qwen3.5-9B LoRA SFT 结果审计

## 范围与口径

本审计针对 shougang-5415 的第一轮 Qwen3.5-9B LoRA SFT，使用正式导出的
4,332 条训练样本、541 条验证样本和 542 条冻结测试样本。每个原始样本
在 parquet 中包含 Stage-1 与 Stage-2 两行训练轨迹，审计统计均按唯一
`source_id` 折叠为单个样本。

训练使用最后一个 checkpoint `global_step_270`，没有根据测试集选择 checkpoint。
训练、验证、测试数据，训练配置，checkpoint 元数据、合并模型与逐样本评测报告
均已用 SHA-256 冻结。完整文件清单由 `audit_sft_results.py` 生成的
`audit-summary.json` 保存。

## 复算结果

| 指标 | SFT |
|---|---:|
| Stage-1 Recall@5 | 95.02% (515/542) |
| 类别准确率 | 94.46% (512/542) |
| 类别 Macro-F1 | 0.9016 |
| 等级准确率 | 98.89% (536/542) |
| 等级 Macro-F1 | 0.9799 |
| 严格联合准确率 | 93.91% (509/542) |
| 正确类别已进入 Top-5 时的 Stage-2 类别选择准确率 | 99.42% (512/515) |

这说明剩余类别错误主要在 Stage-1，而不是 Stage-2 重排。

## 训练—测试重复与分组泄漏

| 检查项 | 测试样本数 |
|---|---:|
| `source_id` 与训练集重复 | 0 |
| 四个元数据字段完全相同 | 1 |
| 归一化后的“字段名 + 表名”完全相同 | 1 |
| 字符三元组相似度 >= 0.95 | 2 |
| 字符三元组相似度 >= 0.90 | 43 |
| 表名在训练集中出现过 | 528 |
| 表名在训练集中未出现 | 14 |

唯一的完全重复样本和另一条相似度 >= 0.95 的样本都预测正确。排除这两条后，
严格联合准确率仍为 93.89% (507/540)；排除全部 43 条相似度 >= 0.90 的样本后，
严格联合准确率仍为 93.39% (466/499)。因此，少量近重复样本不能解释整体高分。

然而，当表名在训练集出现过时，严格联合准确率为 94.89% (501/528)；在 14 条
未见表样本上只有 57.14% (8/14)。未见表样本较少，不能把该数字当成稳定的
总体估计，但它是一个明确的警告：当前随机切分主要测量“已见业务表中的新字段”，
不足以单独证明对新表或新业务系统的泛化。

## 错误分解

33 条严格联合错误分解如下：

- 27 条 Stage-1 漏召回；其中 3 条同时等级错误。
- 3 条在正确类别已进入 Top-5 的情况下被 Stage-2 选错。
- 3 条类别正确但等级错误。

测试集覆盖 144 个类别，其中 39 个类别只有 1 条样本，72 个类别只有 2–4 条样本。
110 个测试集中出现的类别 F1 为 1.0，8 个类别 F1 为 0；这 8 个类别的测试样本
均在 Stage-1 失败。主要混淆对包括：

- `——` -> `出厂管理` (3)；
- `工程合同管理` -> `运输合同管理` (2)；
- `热轧出入库管理` -> `冷轧出入库管理` (2)；
- `公用基准数据` -> `物流管控-司机情况汇总` (2)；
- `铁前生产实绩` -> `作业线设备管理` (2)。

完整的 193 x 193 混淆矩阵、错误相关类别的可读热图和 33 条错误样本表
由审计脚本生成。

## 等级任务诊断

193 个训练类别中，只有类别 `——` 在训练集中对应多个等级（L1: 36，
L2: 175，L3: 29），其他 192 个类别都是固定等级。仅使用“训练集中该类别的
多数等级”这个查表规则，就能在测试集上达到 98.15% (532/542) 的等级准确率。

这里的“多等级”是 193 类口径只使用 `level_4` 文本时产生的折叠现象。
回查原始数据后发现，`——` 实际隶属于 11 条不同完整路径；将四层路径作为类别
身份时，203 条路径均只对应一个固定等级，不存在路径级标注冲突。详见
[`2026-09-18-shougang-raw-label-audit.md`](2026-09-18-shougang-raw-label-audit.md)。

因此，SFT 的 98.89% 等级准确率主要表明模型学会了“类别/业务路径 -> 等级”映射，
不能单独作为复杂等级推理能力的证据。模型相对 193 类的多数等级查表规则额外
做对 4 条；其中 `——` 子集等级准确率为 26/28，说明模型也利用了元数据中的
路径相关信号。

## 结论和下一步

1. 当前 93.91% 严格联合准确率不是由 source-id 泄漏或极少量完全重复样本造成的。
2. 当前切分存在很高的表名交叉，且未见表的小样本结果明显更差；因此需要补做
   按表或业务系统分组的冻结切分。
3. 下一轮应优先优化 Stage-1 召回，因为 30 条类别错误中有 27 条是 Top-5 漏召回；
   Stage-2 在 gold 已召回时已达 99.42%。
4. 在进入 DPO/GRPO 前，应先建立按表分组的验证/测试集，并保持原 542 条测试集不再
   用于调参。
